# data-modeling

**You are authoring the data layer of IqbalAI v2.** This skill encodes the locked model patterns in `docs/ARCHITECTURE.md` §4 so the model is right *before* a migration is generated from it (the model is the source of truth — migrations are autogenerated from it, §4.12). Get the model right and the migration, the typed client, and the API schemas all inherit correctness.

## Why this skill exists

Models are the foundation everything sits on; a wrong model is the most expensive thing to fix later. The recurring failure classes this prevents:

- **FK with no `ON DELETE` / no index** — silent default behavior + slow joins that surface only under load.
- **Free-text `status` strings** instead of enums — invalid values leak in, comparisons are string-compares.
- **Naive timestamps / `timestamp` without tz** — off-by-hours bugs the moment a parent abroad logs in.
- **Everything nullable** (SQLAlchemy's default) — the DB stops being a source of truth.
- **`JSON` instead of `JSONB`, or a JSON blob where a child table belonged** — unqueryable, unindexable data.
- **Hand-built `id`/`created_at`** instead of the locked mixins — inconsistent tables, drift three years in.

## When to apply this skill

Load it when you are about to write or change a SQLAlchemy model: a new table, a new/changed column, a foreign key, an enum, an index, a constraint, or a relationship. If you're only touching repository queries, services, Pydantic schemas, or a migration file, you don't need it (those are stack-enforcer / phase-complete-review territory).

## How to apply

For each model you write or change, walk Rules 1–9 in order. State any violation, state the fix, then write the corrected model. The model is the source of truth: write it correctly, then `alembic revision --autogenerate` → review → one concern per migration (§4.12). Never hand-write a migration from a ticket's data sketch — the ticket shapes are *intent*.

## Rule 1 — Compose the locked mixins; never hand-roll id/audit columns

Every tenant-scoped table composes `IdMixin, AuditMixin, SoftDeleteMixin, TenantMixin` (§4.2–4.5). PK is **application-generated UUIDv7** (`uuid7`), column always `id`. Table name is **plural snake_case**; FK columns are **`<singular>_id`** (§4.1).

```python
# CORRECT
from app.db.base import Base, IdMixin, AuditMixin, SoftDeleteMixin, TenantMixin

class Lecture(Base, IdMixin, AuditMixin, SoftDeleteMixin, TenantMixin):
    __tablename__ = "lectures"            # plural snake_case
    teacher_id: Mapped[UUID] = mapped_column(ForeignKey("users.id", ondelete="SET NULL"), nullable=True, index=True)

# WRONG — hand-rolled id + audit, singular table, bigserial
class Lecture(Base):
    __tablename__ = "lecture"             # singular
    id: Mapped[int] = mapped_column(primary_key=True, autoincrement=True)   # not UUIDv7
    created = mapped_column(DateTime)     # naive, wrong name, not from AuditMixin
```

Reference/lookup tables that aren't tenant-scoped still take `IdMixin, AuditMixin` (skip Tenant/SoftDelete only with reason).

## Rule 2 — NOT NULL is the default; nullability needs a reason

Override SQLAlchemy's nullable-by-default: every column is `nullable=False` unless it's genuinely optional (§4.7). NULL is fine for optional FKs, optional free text, and event timestamps that may not have happened (`published_at`, `archived_at`, `deleted_at`).

```python
title: Mapped[str] = mapped_column(String(500), nullable=False)        # CORRECT
published_at: Mapped[datetime | None] = mapped_column(nullable=True)   # CORRECT — event may not have happened
# WRONG: title: Mapped[str | None] = mapped_column(String(500))        # implicit nullable required field
```

## Rule 3 — Every foreign key: explicit `ON DELETE` + an index

No silent defaults (§4.6). Choose: **RESTRICT** (default — protect the parent), **CASCADE** (child has no meaning without parent — versions/chunks/ratings/annotations), **SET NULL** (informational — e.g. `created_by`, `teacher_id`). Index every FK column (Postgres won't).

```python
# CORRECT
lecture_id: Mapped[UUID] = mapped_column(ForeignKey("lectures.id", ondelete="CASCADE"), nullable=False, index=True)
# WRONG — no ondelete, no index
lecture_id: Mapped[UUID] = mapped_column(ForeignKey("lectures.id"), nullable=False)
```

Locked cascade defaults: `lectures→lecture_versions/chunks/ratings` CASCADE; `schools→users` RESTRICT; `users→highlights/mistakes/study_plans` CASCADE; `users→lectures` (teacher) SET NULL. New relationships declare their choice + rationale (checked in PR review).

## Rule 4 — Enums: native Postgres enum for stable values, reference table for editable ones

Stable, business-logic values (roles, lecture types) → Postgres native `Enum` from a Python `StrEnum`, named `<table>_<column>_enum` (§4.9). Frequently-changing / admin-editable / metadata-bearing values (subjects, exam types, personas) → a **reference table** with a FK (§4.16). Never a free-text status column.

```python
# CORRECT — stable -> native enum
class LectureType(StrEnum):
    STANDARD = "standard"; DIAGNOSTIC = "diagnostic"; REVIEW = "review"
kind: Mapped[LectureType] = mapped_column(Enum(LectureType, name="lectures_kind_enum"), nullable=False)

# CORRECT — editable -> reference table
subject_id: Mapped[UUID] = mapped_column(ForeignKey("subjects.id", ondelete="RESTRICT"), nullable=False, index=True)

# WRONG — free-text status
status: Mapped[str] = mapped_column(String(20))   # "activ", "Active", "ACTIVE" all leak in
```

Enum changes are additive only (`ADD VALUE`); rename/remove is a multi-step migration.

## Rule 5 — Timestamps: `timestamptz` in UTC, tz-aware, DB-set

All timestamps are UTC `timestamptz` (§4.14). `created_at`/`updated_at` come from `AuditMixin` (DB server-side default + trigger) — the app never sets them. No naive `datetime`, no `timestamp`-without-tz, no date-only column unless date is the real semantic (`exam_date`).

```python
# CORRECT — from AuditMixin; app passes nothing
class Lecture(Base, IdMixin, AuditMixin, ...): ...
exam_date: Mapped[date] = mapped_column(nullable=False)   # date IS the semantic — fine
# WRONG
created_at: Mapped[datetime] = mapped_column(DateTime, default=datetime.now())  # naive, app-set, no tz
```

## Rule 6 — `JSONB` only, with a Pydantic shape; prefer a child table for relational data

Never `JSON` (§4.10). Use `JSONB` for schema-varying, read-together, small atomic blobs (LLM tool metadata, score breakdowns, cognitive profile), and give every JSONB column a Pydantic schema validated on write. If inner fields get queried/filtered or the data is relational, use a child table instead.

```python
scores_json: Mapped[dict] = mapped_column(JSONB, nullable=True)   # CORRECT + a Pydantic LectureScores model
# WRONG: prefs: Mapped[dict] = mapped_column(JSON)                # raw text, unqueryable
# WRONG: a JSONB column holding a list of rows that you later filter by an inner id -> use a child table
```

## Rule 7 — Push invariants to DB constraints; explicit string lengths

DB constraints can't be bypassed by buggy code; Pydantic can — do **both** (§4.15). Use `CHECK` for ranges/formats, `UNIQUE` for uniqueness invariants. Strings have explicit max lengths; bare `String`/`VARCHAR` without length is forbidden (`Text` only for paragraph content) (§4.8).

```python
# CORRECT
rating: Mapped[int] = mapped_column(CheckConstraint("rating BETWEEN 1 AND 5", name="ratings_value_check"), nullable=False)
__table_args__ = (UniqueConstraint("school_id", "name", name="classes_school_name_uq"),)
name: Mapped[str] = mapped_column(String(200), nullable=False)
# WRONG: name: Mapped[str] = mapped_column(Text)   # unbounded for a short field; no length
```

## Rule 8 — Indexes are justified; named to convention

Every index is either auto-required (PK, every FK, `school_id`) or backs a real query pattern (§4.11). Name them `<table>_<cols>_idx`, unique `<table>_<cols>_uq` (§4.1). Don't add speculative indexes; don't omit FK/`school_id` indexes.

## Rule 9 — Soft-delete ≠ cascade; use the versioning pattern for history

`ON DELETE CASCADE` is the *hard*-delete referential rule. **Soft-deleting a parent does NOT soft-delete children** — that's a per-relationship service decision, documented in the service (§4.17). Deletion is soft by default (`SoftDeleteMixin`); hard delete needs a migration-comment rationale (§4.4). For entities needing history (lectures, lesson edits), use the immutable **`X` + `X_version`** pattern — versions are append-only, never updated (§4.18).

```python
# CORRECT — current + immutable versions
class Lecture(Base, IdMixin, AuditMixin, SoftDeleteMixin, TenantMixin):
    current_version_id: Mapped[UUID] = mapped_column(ForeignKey("lecture_versions.id", ondelete="RESTRICT"))
class LectureVersion(Base, IdMixin, AuditMixin, TenantMixin):     # append-only, no SoftDelete
    lecture_id: Mapped[UUID] = mapped_column(ForeignKey("lectures.id", ondelete="CASCADE"), nullable=False, index=True)
    version_num: Mapped[int] = mapped_column(nullable=False)
```

## After the model: align the `…Read` schema

When the model is correct, ensure each Pydantic `…Read` schema's fields are a true **subset** of the model's columns (no field the column doesn't back). This feeds the `response_model=`/typed-client correctness (the schema↔model alignment T-230/T-225 check). Wiring `response_model=` itself is router work, not this skill.

## Workflow

1. **Identify the change:** new table? new column/FK/enum/index/constraint/relationship?
2. **Walk Rules 1–9.** For each, ask: does the model comply? Fix before writing.
3. **Compose the mixins first**, then feature columns, then constraints/indexes in `__table_args__`, then relationships.
4. **Then** `alembic revision --autogenerate` → review the diff → one concern per migration (§4.12). The model is the source; never hand-write the DDL from a ticket sketch.

## What this skill does NOT cover

- **Repository queries, layer purity, single-chokepoint imports** → `stack-enforcer`.
- **Pydantic API request/response schemas + `response_model=` wiring** → router/schema work + the `response_model` CI gate.
- **Alembic migration mechanics + the PR-time schema-review checklist (§4.20)** → `phase-complete-review`.
- **Business logic / service invariants** → services + their tests.
- **Multi-tenancy enforcement (RLS, the cross-tenant denial test)** → §3.7/§3.13 (the *pattern* is here via `TenantMixin`; the test lives in the feature).
